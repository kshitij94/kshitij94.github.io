Line Tracker Robot

Goal of the project is to create a robot car that can follow a given path.

This project utilizes the ELEGOO robo kit, which includes an Arduino microcontroller and ITR20001 photoelectric sensors. The sensor incorporates three infrared emitter-receiver pair and an NPN phototransistor. The sensor detects reflected infrared light, enabling the detection of surface reflectivity variations (light/dark, color) and proximity. Three independent sensors are employed, each providing an analog output corresponding to the reflected light intensity. By reading these analog values via the Arduino's analog input pins, we can determine which sensor(s) are detecting the black line. This information is then used to implement a line-following algorithm, controlling the robot's motors to maintain the desired trajectory.

Collision Avoidance Robot

Goal of the project is to create a robot car that can explore the room without colliding into objects.

This project utilizes the ELEGOO robo kit, which includes an Arduino microcontroller and HC-SR04 ultrasonic sensor sensors. The principle of ultrasonic distance measurement is that the transmitter emits ultrasonic waves in a certain direction and starts timing at the same time of the launch moment. The ultrasonic waves travel through the air and returns immediately when encountering obstacles. Then the ultrasonic receiver stops timing immediately when receiving the reflected waves. According to the recorded time and the known condition that ultrasonic propagation speed in the air is 340m/s, the distance between the ultrasonic module and the obstacle can be obtained. While moving, the car actively checks for obstacles within 30 cm. Upon detection, it uses a servo to sweep the ultrasonic sensor left and right, then turns to the clear path and proceeds.

Forward Kinematic with 2 DOF Arm

Goal was to master 3D printing and core ROS concepts, including controllers, URDF, and launch files, through the hands-on development of a 2-DOF robotic arm.

This project focused on the design and implementation of a 2-DOF robotic arm, emphasizing practical application of 3D printing and core Robot Operating System (ROS) functionalities. The arm's mechanical structure was designed in SolidWorks and precision-fabricated using a Prusa 3D printer. Critical to assembly was the accurate measurement of components like SG90 servos, necessitating the use of calipers for precise fitment. Subsequently, attention shifted to ROS for robotic control. Leveraging ROS, the SolidWorks model was imported, and URDF files were generated to define the arm's kinematic structure (joints and links). ROS controllers were then employed to command joint movements. The project specifically focused on forward kinematics: translating user-input joint angles into physical movements. This involved serial communication (C++) between ROS and an Arduino, which actuated the arm's motors. While lacking AI, the project demonstrated the arm's capability to execute predefined, hardcoded paths, analogous to applications like automated painting. rViz proved indispensable for simulating the arm's behavior and debugging control algorithms prior to deployment on the physical hardware.

3D printing ball bearings

Ordering a metal ball bearing can become very expensive for large-scale applications.

To keep the cost low, I designed and 3D printed a custom ball bearing which uses 4.5mm steel balls. The mechanism is pretty cool: the outer housing of the ball bearing has a dedicated entry hole where the balls can be fed inside the bearing, which is then secured by inserting a custom cork to close the hole.

The entire model was designed in Fusion 360 using its Python API. The script is input dialog-driven, allowing the user to dynamically enter the desired outer diameter to generate and print the respective ball bearing.

3 DOF Arm - Base Joint

Standard stepper motors are characterized by high speed but low torque, which is often the opposite of what a robotic arm requires. By integrating a gearbox, you can exchange that excess speed for significantly higher torque and smoother, more controlled motion. This mechanical advantage is essential for achieving the precision and lifting capacity necessary for robotic applications.

I chose to design a cycloidal drive because it is easy to 3D print and offers virtually zero backlash or jitter. With a 21:1 reduction ratio, the drive effectively converts the stepper motor's 59 Ncm of torque into an output of 130 Ncm. While a 21:1 ratio requires 21 full motor rotations for every single output rotation, this mechanical advantage provides the precision and strength necessary for high-accuracy applications.

3 DOF Arm - Joint 1

Joint 1 is the most difficult joint because it needs to be able to support high torque. With cheap motors (such as this NEMA 17 Stepper Motor), we designed a cycloidal gearbox to convert the speed into high torque.

In the base joint, we used only one cycloidal disk, but because of the vertical movement, there was jerk while the arm was coming down. To combat that, we added another disk 180° out of phase to counter the jerk while coming down. That seems to have stabilized the motion a lot.

Earlier we were using DRV8825 stepper drivers, which were not able to provide enough current and were blowing up. We switched to DM542TE, which allowed more current to flow safely without frying the Arduino. For testing, we attached a weight of 500 grams at a distance of 10 cm from the gearbox, and the box was able to move without skipping steps.

Another improvement we did was in the Arduino code, where we started using microsteps (8x) and reduced the speed and acceleration for smooth movement.

#include <AccelStepper.h>

// --- Hardware Pins ---
const int dirPin = 2;
const int stepPin = 9;

// --- Physical Setup ---
const int numRollers = 15;                   // Updated for your 15-roller gearbox (14:1 ratio)
const float reductionRatio = numRollers - 1; 
const float motorStepsPerRev = 200.0;        // Standard NEMA 17
const float microstepping = 8.0;             // Updated for 8x microstepping (1600 steps/rev)

// --- Target ---
const float targetOutputDegrees = 60.0;      // Updated to 30 degrees

// Calculate steps using round() to avoid decimal truncation
long X_steps = round(((motorStepsPerRev * microstepping * reductionRatio) / 360.0) * targetOutputDegrees);

AccelStepper stepper(1, stepPin, dirPin);

// --- Timing and State Variables ---
unsigned long pauseStartTime = 0;
const unsigned long waitDuration = 2000;     // 5 seconds pause in milliseconds
bool isWaiting = false;
int moveDirection = 1;                       // 1 for forward, -1 for backward

void setup() {
  Serial.begin(9600);
  
  stepper.setMaxSpeed(800);                 // Increased maximum speed capacity for microstepping
  stepper.setAcceleration(700);              // Smooth acceleration ramp

  Serial.print("Reduction Ratio: ");
  Serial.println(reductionRatio);
  Serial.print("Steps to move output 30 degrees: ");
  Serial.println(X_steps);

  // Command the first movement
  stepper.move(X_steps * moveDirection);
}

void loop() {
  // Always call run() so the library can process steps dynamically
  stepper.run();

  // Check if the motor has reached its target position
  if (stepper.distanceToGo() == 0) {
    if (!isWaiting) {
      // Motor just finished moving; start the 5-second timer
      pauseStartTime = millis();
      isWaiting = true;
      Serial.println("Target reached. Waiting 5 seconds...");
    } else {
      // Check if 5 seconds have passed
      if (millis() - pauseStartTime >= waitDuration) {
        isWaiting = false;                   // Reset waiting flag
        moveDirection = -moveDirection;      // Reverse the direction
        
        Serial.print("Moving in opposite direction: ");
        Serial.println(X_steps * moveDirection);
        
        stepper.move(X_steps * moveDirection);
      }
    }
  }
}
